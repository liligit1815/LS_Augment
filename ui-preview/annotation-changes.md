## 新增需求

1. 应用增强页增加“应用商店同时下载限制解除”开关与详情。原型不实际控制应用商店。
2. 步数计划分两步：先设开始/结束时间、随机执行次数、每次步数；再多选周一至周日。显示每日合计、随机时间示例，支持跨午夜时间范围。关闭计划后隐藏计划设置。实际执行留待手机模块阶段。
3. 模块设置新增 JSON 配置导出、导入。已验证实际下载、文件选择导入、刷新恢复及无效文件拒绝。内容包含当前原型设置，不包含账户绑定和执行日志。

## 后续落地约束

- 本轮确认的是界面原型，不是已安装模块的新功能。
- 模块阶段应使用稳定设置键和版本化 JSON 格式，并实现设置迁移；不能直接把原型的控件路径键当作长期模块协议。
- 自动保存不等于所有底层功能立即生效：保留重启作用域入口，模块阶段按各功能实际生效方式处理。

统一交互：简单功能显示「名称＋开关」；含配置的功能显示「名称＋开关＋展开箭头」。关闭后隐藏参数并禁用展开箭头，开启后展开配置，可独立手动收起；开关关闭不丢失已经填写的参数。有效输入、选择、滑杆即时保存，无效输入保留上次有效值并显示原因。桌面名称改为输入即保存，图片在裁剪完成后保存，取消单独的「确认修改」。

没有原生布尔开关的14项独立值覆盖，在原型增加配置入口开关：关闭时使用原厂 / 无覆盖值并记住最后选择，重新开启恢复。点击开启后允许填写默认值，不会在输入过程中自动关闭、折叠。数值默认值按数值比较（如1与1.0相同）。这些新增入口开关属于本轮UI方案，不表示已经修改Android配置结构。

状态栏布局的主开关仅出现一次，布局预览和四个分页收进其配置区域。肩键两个功能保持独立；极速连点通过测试前禁用。健康绑定和设备测试等前置操作保留，电池只读数据改为可展开的查看操作。

本轮实现：`current-application.tsx`、`current-feature-groups.json`、`current-feature-input.tsx`、`current-feature-state.ts`、`current-maintenance.tsx`及原有当前页面控件。历史基准与旧标注文件未覆盖。操作验证与并排对照见 `design-qa.md` 的本轮记录。

# LS_Augment 界面原型

## UI 规范与实现授权

所有原型及原生界面设计必须先阅读并遵循[红魔Duo UI规范](../docs/红魔Duo-UI规范.md)，以当前主页、模块、关于公共组件为基准。现行规范与用户最新明确要求优先于历史标注和顶边对齐要求。

二级及更深页面的路径导航底边到首个分组标题（无标题时为首个内容控件）总间距为 8–12dp，默认 8dp；网页在对应移动端逻辑视口以同等逻辑像素表达。不得为对齐主页聚合卡片顶边增加空白。

用户已授权把确认的主页分组、多级导航、单分组直达、独立路径栏、控件尺寸和功能卡片布局实现到 Android。这覆盖历史“仅做网页原型”的限制，须保留真实功能、配置键、校验、隐藏入口解锁和资源草稿保护。其他未经确认的网页设计不因此自动转入手机模块。状态栏当前使用组件排列，旧表格设计不作为现行功能入口。

## 当前代码与目录边界

Android 源码版本为 test20496。网页入口为 `app/current-prototype.tsx`，已同步当前 13 分类导航及部分编辑界面；`current-catalog.json`、`current-editor-data.json`、`current-editor-help.json` 和 `current-scope.json` 含历史源码快照，不能代表全部当前手机功能。当前功能见[最新版功能说明](../docs/最新版功能说明.md)。

`scripts/ExportCurrent.java` 和 `scripts/sync-current.mjs` 维护目录数据。后续改版继续在现有原型迭代，不重新导入旧目录覆盖确认的修改。`native-pages.json` 和 `layout-overrides.ts` 保存历史实测控件与覆盖，保留作设计上下文。截图、逐次标注及过程记录留在本地，不作为源码仓库必需文件。

## 还原与操作约束

- 以当前手机截图、Android 页面源码及实测控件为依据，不凭印象简化，不套用新的设计风格。
- 页面文字、字体、图标、位置、尺寸、卡片结构、分页、滚动边界和展开状态均属于还原范围。
- 用户标注引起的布局变化优先落实到当前页面；需要数据覆盖时使用 `app/layout-overrides.ts`，不要重新导入基准覆盖已经确认的修改。
- 保留 `data-native-path` 和 `data-ui-label`，用于将标注对应到真实控件。
- 网页是独立原型，开关、输入和应用操作不得调用手机或执行实际 Root、隐藏、重启、健康数据等操作。
- 保留已有 Sites/Vinext 项目结构，不重新初始化、创建第二个 Site 或更改访问范围。
- 修改后比较同页面、同设备、同字号、同状态和同尺度的真机与网页截图，并核对实际边界。浏览器截图按嵌入的 ICC 色彩描述转换为 sRGB 后再比较颜色；JPEG 预览不能替代带 ICC 的 PNG。
- 本地原型交付时保留服务和右侧浏览器页面，后续直接在该原型上迭代。

历史对照视口曾使用 1000×883，手机逻辑视口为 374.15×827.08 CSS 像素、截图为 1216×2688；新对照应按当前设备与逻辑尺度核对。`scripts/compare-current.py` 先转换 sRGB，再同尺度裁剪，所需输入单独准备。

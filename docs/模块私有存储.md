# 模块私有存储

红魔Duo的配置、缓存和恢复记录由模块应用持有。目录通过模块自身的 `Context` 获取，遵循当前 Android 用户的应用隔离；Hook 进程通过受控 Provider 访问，不在系统目录、宿主应用目录或公共目录新建模块存储。

开机配置通过 LSPosed 官方 remote preferences 接口发布，保留框架代管的持久副本。模块不指定框架内部路径，不另建启动快照，也不扩大应用目录的读取权限。手机端负责保存、迁移和清理，电脑工具仅用于开发。

## 数据归属

竞技键类别、上下推动作、应用与 Base64 编码的多行命令保存于模块私有配置。原厂 `Settings.System.fourth_physical_key_function_value` 是手机原生操作设置，模块启用时仅将它设为原厂空动作 `0`；原值与恢复责任保存在 `module-system-settings-v1`，关闭时比较当前值后单项恢复，不覆盖外部修改。双卡信号的平铺／荣耀双排／iOS双排选择与模块双排信号共用已有私有字段；样式字段 `ls_augment_rm_signal_dual_style` 保存 0（荣耀）或 1（iOS），关闭双排或切换平铺时保留。原厂三项选择通过同一次私有配置提交保存开关与对应样式，旧布尔选择协议仍保留以兼容未重启的旧Hook。原厂 Settings 只通过身份校验的配置桥读写，不新建系统 Settings 镜像。

下表的 `files/`、`cache/`、`databases/` 和 preferences 均属于模块应用内部存储。恢复原值、未完成事务和历史记录使用持久存储；能够从原始数据重新生成的派生文件才使用缓存。

| 数据 | 当前存储 | 访问与保留规则 |
|---|---|---|
| 通用配置、诊断与熔断状态 | `AppConfig`、私有诊断存储、`ls_augment_crash_fuse_v2` preferences | 配置桥提供读取；旧熔断状态持久保存后才删除旧 Settings 键 |
| 最近任务圆角范围 | `recents-card-radius-range-v2` preferences | 桌面采样后通过 Provider 发布，界面读取已保存范围；样式、尺寸或方向变化后更新 |
| 极暗归属和原生设置恢复记录 | `module-system-settings-v1` preferences | 模块保存归属与原值，system_server 通过限定身份的接口读取 |
| 超分辨率与补帧恢复记录 | `native-gfrc-recovery-v1` preferences | `GfrcRecoveryStore` 比较旧值后更新；原生状态恢复完成前不能清除责任 |
| 隐藏名单、历史、凭据和未决事务 | `files/hide-recovery/v2` | `HidePrivateStorage` 以模块应用 UID 执行存储；迁移只搬运记录，不重放隐藏操作 |
| 退休 Root 模块原始记录 | `files/legacy-root-v1/original` | 原样归档已识别旧文件，清单记录摘要和来源；不重新应用退休策略 |
| 桌面网格恢复记录和页面配置 | `launcher-grid-recovery-v1`、`launcher-page-state-v1` preferences | 仅允许对应桌面调用方访问；接回配置时保留现有图标布局 |
| 原子工作台启用、外观与恢复 | 主配置键 `atomic_workbench_enabled`、`atomic_workbench_show_media`、`atomic_workbench_empty_side_slots`，`files/atomic_workbench/recovery-window-{0..3}.json` 和逐窗私有会话锁 | Root 原子写入 UID／用户／显示／任务、显隐恢复证据与原生 Home 的任务及组件身份，文件归模块 UID、0600；兼容旧 `recovery.json`，全重置先确认 Home 和应用均恢复再清理；媒体内容仅留内存，不落盘 |
| 原子工作台启动诊断 | `files/atomic-workbench.log`、`diagnostic-retention` 中的写入／轮转状态 | Root只向进程管道输出结构化事件，由应用UID持久化；有界256KiB、保留完整行、统一导出；会话凭据脱敏，重置代际阻止旧连接回写，全重置随应用私有文件清理 |
| 健康倍率、计划、去重与限额账本 | `databases/health-step-ledger-v1.db` | 受控 Provider 与数据库工作线程访问；原厂健康数据库仍由健康应用管理 |
| 连招速度派生文件 | `cache/combo-motion-v1` | 模块读取只读源 FD，转换后提供只读结果 FD；宿主仅保留内存索引和播放租约 |
| 肩键实体采集 | 模块 cache 的临时租约、`files/rapid-capture-v1` 的恢复责任 | 唤醒硬件前保存责任，确认采集停止且硬件恢复后才清理；跨用户互斥使用已验证驱动 FD 的内核锁 |

连招缓存限定数量、总大小和播放描述符数量；缓存淘汰不提前关闭活跃播放持有的 FD。原厂消费者每次打开得到独立读取位置，缓存丢失时回退原始录制并按需重新生成。派生文件不会复制回游戏助手目录。

## 跨进程边界

- test20568 的桌面手动空页来源 `empty_origins` 保存在模块原有桌面私有状态中，限定当前真实数据库的用户、存储域、路径摘要、设备号及 inode。旧页号保留用于排序，不自动作为创建空白页的依据；不把原厂图标或数据库内容复制入模块状态。
- 用户主动导出诊断时，`LauncherNativeCrashEvidence` 在手机 Root 内只读当前用户原厂桌面的5个固定偏好文件，仅解析3条首栈摘要及时间、恢复状态。原文件不修改，原 XML、其他偏好、路径和异常消息不导出；应用端严格校验子进程协议，非预期输出整体脱敏。原厂历史缺失按未知处理。
- Provider 在清除 Binder 身份前按接口需要捕获调用身份；使用 UID、包名及包归属信息限定系统、桌面、游戏助手或健康应用，并核对 Android 用户。
- 请求只接受固定结构、版本和允许的数据范围，不接受任意目标路径。文件接口校验 URI、模式、摘要和文件类型，只提供必要的只读 FD。
- Hook 的绘制和系统回调使用内存快照，存储访问、观察注册和同步提交在工作线程完成。
- 私有保存成功后才继续原生变更或旧源删除，不将提交失败后的 SharedPreferences 内存值视为持久成功。
- 恢复记录采用事务或比较更新，重复请求不能覆盖其他操作的新状态。暂时不可用时保留原记录并重试，不能用空状态替代现有配置。
- 原子工作台仅允许 UID0 将手机 Root Binder 登记到一次性启动会话；应用调用控制接口时校验 UID、协议和会话凭据，凭据通过进程标准输入传递，不写命令行或日志。显示、任务、输入与恢复在 Root 工作线程串行执行，跨进程私有文件锁避免新旧恢复进程并发操作同一记录。
- test20557 的逐窗恢复记录增加兼容字段 `home_migration_pending`。它标记原生 Home 迁移尚须核对实际父容器、显示缓存和迁移完成状态，不能只因缓存显示号为 0 就清除责任。缺少该字段的旧记录仍可读取。
- 工作台诊断 `rootSessionId` 是独立随机关联号，不是控制会话凭据；统一导出仅统计保留日志中的开头、结尾和序号缺口，旧版 PID 分组标明身份不完整。新增 Duo 退出信息仅覆盖应用进程，不能证明独立 Root 进程的完整终止原因。

## 旧数据迁移与清理

迁移由 `LegacySettingsMigration`、`ExternalStorageMigration` 和对应功能迁移器协调。旧来源仅用于受限读取、核对和清理，不再作为新数据写入位置。

1. 核验当前用户、固定旧路径、归属、类型、大小和链接关系。历史全局隐藏记录仅由主用户接收。
2. 保存到模块私有存储，确认内容、提交结果及必要的文件和目录同步；数据库迁移核对完整性和记录。
3. 再次检查旧源身份、内容及写入进程。仅在私有副本完整且旧源未变化时清理对应旧文件或精确 Settings 行。
4. 核验删除结果，并仅移除已确认归属且为空的旧目录。未知相邻数据、活跃旧写入者和无法确认的恢复责任继续保留。

Settings 旧数据包含模块自定义配置、极暗归属和 GFRC 恢复记录。GFRC 使用限定旧键的 `ContentResolver.delete/query` 真正删除行，不以 `putString(null)` 代替删除；迁移不允许插入、更新或通配删除系统表。旧熔断状态先迁入私有存储，旧进程可能写回的数据在后续启动继续复核。

固定旧文件来源包括 `/data/adb/ls_augment`、`/data/system/ls_augment/boot-config-v1`、桌面的模块 preferences、健康应用的模块账本及游戏助手的模块派生缓存。迁移保留原始证据，不移动或删除宿主自己的配置、录制和数据库。旧肩键 `/dev` 会话等待旧进程释放；新会话不再创建外部锁文件。

已退休电池覆盖必须先恢复原厂关系并确认旧源未重新挂载，才删除精确旧文件。无法证明恢复成功时保留证据。`BootConfigMirror` 与旧启动文件读取器已删除，新配置发布使用官方框架接口。

全部重置先暂停相关工作并完成原生状态恢复，再删除模块数据。尚未完成的恢复、损坏或未知责任不能被普通缓存清理或全局重置吞掉；已完成的归档可随明确的全部重置清理。

## 原生功能与用户导出

原厂设置、硬件节点、桌面布局和游戏选中项是功能实际作用对象，继续使用对应系统或原厂接口。模块用来记录原值、归属或过程的元数据必须留在私有存储。

| 操作 | 保留的原生边界 |
|---|---|
| 开发者选项、USB 调试与安装、刷新率、极暗 | 仅写对应原生键；修改前的模块恢复记录私有保存 |
| 原厂 GFRC 模式与能力属性 | 按功能控制原生状态，模块原值和恢复阶段单独私有保存 |
| 快捷磁贴 | 通过系统接口增删本模块磁贴，重置保留其他磁贴 |
| 桌面、肩键和健康功能 | 原厂布局、方案选中位及原厂健康数据继续由各自应用管理 |
| 用户主动导出 | 配置、素材和日志通过 Android 文档接口写入用户选择的位置 |
| 用户主动导入铃声 | 通过系统媒体库管理，不充当自动生成的模块缓存 |

## 维护入口

存储边界由 `tools/test-settings-private-storage.py` 和 `tools/test-hook-storage-boundaries.py` 检查。迁移与恢复分别由 `test-hide-private-migration.py`、`test-legacy-root-storage-migration.py`、`test-launcher-owned-state.py`、`test-health-private-ledger.py`、`test-combo-private-storage.py`、`test-gfrc-recovery-store.py`、`test-extra-dim-private-client.py` 和 `test-rapid-private-capture.py` 等工具覆盖。

边界扫描用于发现新增写入入口，不能代替调用链审查、Android 权限检查及实际恢复行为验证。新增原生写入或迁移例外必须明确数据归属和清理范围，并补充对应检查；过程日志和设备数据留在被忽略的本地输出目录。

## 单独清空日志

“模块 → 日志 → 清空日志”只清理模块拥有的运行日志、诊断历史、崩溃记录、跨启动证据、开发检查结果及导出临时文件。功能配置、自定义资源、原生状态恢复责任、兼容凭据和实时能力状态保留。崩溃日志保留已打开文件的可写能力，避免清理后漏记新崩溃。

清理时间边界保存在设备保护存储中，用于阻止旧队列、旧进程计数和旧公共历史重新写回。导出期间与清理互斥；已另存的文件以及系统／LSPosed共享日志不删除。普通日志按各自大小轮转，但所有诊断与缓存没有统一总量上限。

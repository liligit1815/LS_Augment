# 项目结构与文件说明

当前版本：`2.0.0-alpha1-test20632`。版本名称与内部版本号统一读取 `android/version.properties`。

|---|---|

| `android/app/src/main/java/ls/augment/com/hook/` | 各原厂作用域的 Hook、实时活动、状态栏、风扇与自动化逻辑 |
| `android/app/src/main/cpp/` | 手机端原生输入与连点实现 |
| `android/app/src/main/res/` | Android 布局、图标、字体、字符串及首次启动视频 |
| `android/app/src/main/assets/` | Xposed 元数据、设备基准、引用许可及模块运行所需素材 |
| `android/app/src/androidTest/` | 设备回归源码与功能场景 |
| `android/gradle/`、`android/gradlew*` | 固定版本的 Gradle Wrapper |
| `tools/` | 源码检查、回归、设备验证、构建与签名辅助工具 |

| `contributors-site/` | 贡献名单网页源码、内联项目图标及图标来源记录 |

| `docs/` | 当前功能、UI 规范、开发说明、素材说明与本版发布说明 |

## 手机端运行关系

“红魔Step”在`AtomicWorkbenchSettingsActivity`启用，`hook/AtomicWorkbenchGestureHook`在系统框架监听手机全局手势并启动独立任务。`AtomicWorkbenchActivity`与纯`AtomicWorkbenchWorkspaceModel`管理内部桌面、应用栏、主区及三个实时侧槽；固定窗口交换视觉角色。`AtomicWorkbenchClient`通过手机Root启动同APK的`AtomicWorkbenchRoot`，经鉴权Provider交接私有Binder；`AtomicWorkbenchEngine`协调四个`AtomicWorkbenchPlatform`及独立账本，负责原任务接入、显示、触摸、IME和逐窗恢复。`AtomicWorkbenchReset`在所有恢复完成前阻止数据清理；工作台不依赖电脑端服务。

`AtomicWorkbenchMedia`与`AtomicWorkbenchNavigation`在当前Root会话内读取对应用户的真实媒体会话及持续导航通知，后者核验实际Root权限和AppOps，不修改宿主权限。`AtomicWorkbenchCardPager`管理音乐与导航的左右切换。`AtomicWorkbenchQuickstepTargetHook`适配原厂各屏原生最近任务，核验真实任务、动画和窗口；`GlassWindowBackdrop`为工作台设置等包含TextureView的独立弹窗复制本Activity窗口画面，受安全窗口、生命周期及内存约束。

`AtomicWorkbenchQuickstepInputHook`分别核验物理入口及主虚拟屏输入；`AtomicWorkbenchLauncherCrashHook`只在已认证工作台的同一次原厂异常处理内保护自动清数据分支，保留原异常与终止。`LauncherNativeCrashEvidence`在手机 Root 内只读并过滤原厂历史首栈摘要，`DiagnosticExport`再校验输出协议。`LauncherDatabaseIdentity`记录数据库来源，`LauncherPageOrigins`把模块显式添加的空页限定到该来源，`LauncherPagesHook`不从无来源旧页号创建空白页。

应用页面通过 `UiKit` 复用控件与视觉样式，功能入口由 `NativeFeatureGroups` 管理。`ConfigSchema` 定义通用配置字段、默认值与范围；`LiftArcOptions` 定义锁屏上滑的 39 项配置。专用编辑器负责布局、素材及其他复杂配置，`LiftArcSettingsEditor` 使用 22 项滑动条与必要的文字、颜色和选项控件。用户修改在手机端保存，由配置桥接提供给相应原厂作用域，锁屏参数共同纳入配置导入、导出及全局重置。

`hook/` 中的模块在对应进程执行，按原厂能力决定是否接管。`DynamicIslandHook` 负责灵动岛实时活动与图标样式，`StatusBarGridHook` 负责状态栏布局，`FanControlHook` 与 `FanRpmStartup` 负责风扇控制与启动读数等待，`ScreenOffAutomationHook` 负责息屏自动化。原厂接口不可用时按对应功能的回退规则处理。

`RedMagicSystemUiHook` 的 `SignalPair` 将双排锚定到物理 SIM 槽位，`SignalDrawable` 将活动数据订阅映射到箭头和素材角色。`DualSignalTint` 记录原厂 `ModernStatusBarView` 真正生效的前景色回调，使用原厂 `DarkIconDispatcher` 判定所在区域颜色；冷启动可读取同一信号视图或绑定持有的有效颜色，未知时恢复原厂。颜色回调只重绘，不重建几何；`StatusBarTintHook` 在最终图形位置重放原厂区域色，`StatusBarGridHook` 在稳定帧派发待更新颜色。`ConnectivityIconState` 按物理槽位保存 SIM，`ConnectivityIconLayout`、`CircleConnectivityPlan` 和 `ConnectivityIconPainter` 按活动数据订阅选择圆环的流量卡与另一张卡角色。

`SystemUiOptions.SIGNAL_DUAL_STYLE` 为双排样式提供荣耀／iOS选择，默认保留荣耀。`IosSignalPolicy` 根据实际信号、无服务状态和原厂前景色选择 `assets/signal/ios/` 中的原始 PNG；`IosSignalAssets` 在工作线程解码，`IosSignalPainter` 供运行时、Duo预览和原厂弹窗共享等比绘制。`DualSignalLayout.single()` 与单行间距计划使单卡使用真正一行，双卡仍按固定物理槽位上下排列。

`NotificationStackPolicy` 管理大堆叠合并、分类内同应用小堆叠及独立展开状态。总开关只启用功能，大小模式均关闭时保留原厂列表，仅小模式直接按应用收起，仅大模式展开后逐条显示，两项同时开启时显示大堆叠与应用堆叠两层。`NotificationStackHook` 在手机端原生列表计算前应用可见成员，识别首卡短按并展开当前堆叠，保留原始通知、原生通知组和清除范围；国内固件的分类适配复用原厂排序协调器的静默与最小化判定。`NotificationStackDecor` 复用原厂静默标签和卡片背景绘制堆叠边缘，不提供模块箭头。`NotificationAppearanceOptions` 与 `NativeFeatureGroups` 提供同一入口下的大、小堆叠开关；默认关闭，关闭总开关保留子值，旧尾部几何参数仅保留配置兼容。

`NotificationAppearanceHook` 与 `HeaderClockLayout` 管理通知头部时钟格式、大时钟与列表留白；秒数或中文时段开启时，这条路径独立于通知堆叠总开关。`headerLayoutTop` 统一为留白、可用高度和布局失败缓存提供坐标，先将非共同祖先的原厂 `MfvQSContainerImpl` 根动画位移取整，再从屏幕整像素坐标中扣除，保留共同祖先、头部与列表自身的位移。顶部间距写入每次重新读取最新分配，`allocating` 仅保护正在接管的有效布局，原厂资源事务保留已提交留白；初次未提交、关闭相关功能、普通横屏格式模式和空间不足时释放。原厂入场、回弹和其他动画继续运行。

`LiftArcHooks` 在系统界面进程识别锁屏入口，`LiftArcController` 管理手势与视图，`LiftArcUnlock` 转交原厂安全解锁流程；弧形、指示条、玻璃与壁纸遮罩分别由相应视图实现。`LiftArcConfig` 读取配置桥，`LiftArcRuntime` 记录当前进程适配状态及异常暂停，`LiftArcLog` 接入现有日志。关闭功能撤销本功能持有的视图修改并保留参数，作用域重启复用“状态栏（SystemUI）”。

`AuditLog`、`HookTelemetry`、`RuntimeEnvironment` 与 `DiagnosticExport` 共同记录操作、进程及版本信息，并在手机端生成诊断导出；锁屏运行日志随现有查看、复制、清空、分享和统一导出处理，无额外日志开关。模块功能不依赖电脑上的常驻程序；电脑工具仅用于开发、构建和验证。

`ContributorsActivity` 继续显示纯 WebView 贡献名单，正文来自 `contributors-site/public/index.html` 对应的正式网页。构建取得正式网页作为离线内容，页面打开时再刷新；网页内联三个原始图标，仅 HyperCeiler 和 LiftArc 的精确 GitHub 地址可由用户点击交给手机浏览器。引用来源及完整许可保存在 `third_party/LiftArc/` 和安装包许可资源中。

## 仓库与发布边界

仓库保留构建与维护所需的源码、资源、Wrapper、依赖锁、公开证书和回归源码。`docs/releases/` 仅维护当前版本说明，逐次测试和中间候选记录留在本地；历史版本可从 Git 标签和 GitHub Release 查询。

安装包、源码压缩包及校验文件通过 GitHub Release 分发。`out/`、`audit-output/`、构建缓存、依赖目录、截图录像、过程报告、本机配置、私有签名和本地部署元数据均由 `.gitignore` 排除。运行后生成的文件不能因存在于工作区而纳入源码包。

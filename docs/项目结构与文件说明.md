# 项目结构与文件说明

当前版本：`2.0.0-alpha1-test20510`。版本名称与内部版本号统一读取 `android/version.properties`。

## 目录职责

| 路径 | 职责 |
|---|---|
| `android/app/src/main/java/ls/augment/com/` | 原生配置页面、公共控件、配置桥接、诊断与手机端服务 |
| `android/app/src/main/java/ls/augment/com/hook/` | 各原厂作用域的 Hook、实时活动、状态栏、风扇与自动化逻辑 |
| `android/app/src/main/cpp/` | 手机端原生输入与连点实现 |
| `android/app/src/main/res/` | Android 布局、图标、字体、字符串及首次启动视频 |
| `android/app/src/main/assets/` | Xposed 元数据、设备基准、引用许可及模块运行所需素材 |
| `android/app/src/androidTest/` | 设备回归源码与功能场景 |
| `android/gradle/`、`android/gradlew*` | 固定版本的 Gradle Wrapper |
| `tools/` | 源码检查、回归、设备验证、构建与签名辅助工具 |
| `ui-preview/` | 网页原型源码、依赖锁及浏览器样例数据 |
| `contributors-site/` | 贡献名单网页源码、内联项目图标及图标来源记录 |
| `third_party/` | 引用项目的来源、移植范围和许可原文 |
| `docs/` | 当前功能、UI 规范、开发说明、素材说明与本版发布说明 |

## 手机端运行关系

应用页面通过 `UiKit` 复用控件与视觉样式，功能入口由 `NativeFeatureGroups` 管理。`ConfigSchema` 定义通用配置字段、默认值与范围；`LiftArcOptions` 定义锁屏上滑的 39 项配置。专用编辑器负责布局、素材及其他复杂配置，`LiftArcSettingsEditor` 使用 22 项滑动条与必要的文字、颜色和选项控件。用户修改在手机端保存，由配置桥接提供给相应原厂作用域，锁屏参数共同纳入配置导入、导出及全局重置。

`hook/` 中的模块在对应进程执行，按原厂能力决定是否接管。`DynamicIslandHook` 负责灵动岛实时活动与图标样式，`StatusBarGridHook` 负责状态栏布局，`FanControlHook` 与 `FanRpmStartup` 负责风扇控制与启动读数等待，`ScreenOffAutomationHook` 负责息屏自动化。原厂接口不可用时按对应功能的回退规则处理。

`LiftArcHooks` 在系统界面进程识别锁屏入口，`LiftArcController` 管理手势与视图，`LiftArcUnlock` 转交原厂安全解锁流程；弧形、指示条、玻璃与壁纸遮罩分别由相应视图实现。`LiftArcConfig` 读取配置桥，`LiftArcRuntime` 记录当前进程适配状态及异常暂停，`LiftArcLog` 接入现有日志。关闭功能撤销本功能持有的视图修改并保留参数，作用域重启复用“状态栏（SystemUI）”。

`AuditLog`、`HookTelemetry`、`RuntimeEnvironment` 与 `DiagnosticExport` 共同记录操作、进程及版本信息，并在手机端生成诊断导出；锁屏运行日志随现有查看、复制、清空、分享和统一导出处理，无额外日志开关。模块功能不依赖电脑上的常驻程序；电脑工具仅用于开发、构建和验证。

`ContributorsActivity` 继续显示纯 WebView 贡献名单，正文来自 `contributors-site/public/index.html` 对应的正式网页。构建取得正式网页作为离线内容，页面打开时再刷新；网页内联三个原始图标，仅 HyperCeiler 和 LiftArc 的精确 GitHub 地址可由用户点击交给手机浏览器。引用来源及完整许可保存在 `third_party/LiftArc/` 和安装包许可资源中。

## 仓库与发布边界

仓库保留构建与维护所需的源码、资源、Wrapper、依赖锁、公开证书和回归源码。旧版本发布说明保存在对应 Git 标签与 GitHub Release 中，当前目录只维护本版说明。

安装包、源码压缩包及校验文件通过 GitHub Release 分发。`out/`、`audit-output/`、构建缓存、依赖目录、截图录像、过程报告、本机配置、私有签名和本地部署元数据均由 `.gitignore` 排除。运行后生成的文件不能因存在于工作区而纳入源码包。

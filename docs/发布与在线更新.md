# 发布与在线更新

红魔 Duo 的源码、版本和签名构建在 `LS_Augment`，公开 APK 与推送清单在 [liligit1815/lispacerelease](https://github.com/liligit1815/lispacerelease)。本文维护构建、预检查、正式发布与在线核验步骤。更新说明只写用户可见的变化和必要操作。

## 发布顺序与完成条件

1. 修改 `android/version.properties`，内部版本号比前一安装包增加 1，并高于远端清单；显示版本名同步 `-test<versionCode>`。使用现有发行私钥构建并验证 Release，完成本次改动所需回归。
2. 在更新仓库同步 `main`，准备非空 UTF-8 更新说明，运行 `tools/publish.py --app redmagic-duo ... --dry-run`。预检查使用本地清单，必须先同步；它不访问 GitHub。
3. 运行相同命令并去掉 `--dry-run`。工具重新读取远端版本，上传并公开 `redmagic-duo-v<versionCode>` 的 `redmagic-duo-<versionCode>.apk`，核验公开附件后才更新 `main/updates/redmagic-duo.json`。发布身份需能直接向 `main` 提交清单；分支保护或规则集拒绝提交时，即使附件已公开也不表示推送完成。
4. 发布完成后同步本地更新仓库并运行 `tools/validate.py`，再完成下文的公网核对。本地清单与 `out/published/` 回执不能代替公网数据。
5. 同步源码仓库 README 的当前版本、APK 直链和专属 Release 链接。固定清单地址、`appId`、包名及发行证书保持一致。

工具只推进所选软件的清单。每个软件当前只有一个通道，发布 `alpha` / `test` 同样会推送给用户；GitHub 的 Pre-release / Latest 标记不参与客户端版本判断。

中断后先检查公网清单及对应附件，再用同一 APK、同一更新说明、同一命令重试。清单提交的响应丢失时，远端可能已经成功更新。工具可复用校验一致的附件，但不会用同版本号换包；重试改变说明只会更新清单中的 `notes`，不会同步改写既有 Release 正文。已公开 Release 缺少预期附件、附件大小或哈希不符、签名变化时应先排查。修正已推送的 APK 需要增加版本号，不能覆盖旧标签或附件，也不能手动降低清单版本来修复。

PowerShell 默认不会因外部程序退出码非零而停止。执行构建、同步、预检查、发布和验证时应检查每一步的退出码；发布失败后不能继续用本地清单验证通过作为发布成功的依据。

## 发布命令

先用 `tools/build-release.py --previous <上一安装包路径>` 构建递增版本的同签名 APK。该工具使用离线 Gradle 依赖缓存，首次开发环境需先准备依赖；签名参数见[签名说明](../tools/signing/README.md)。同版本已生成的正式安装包应直接复用，不重新构建替换。

以下命令从源码仓库根目录开始，假定更新仓库位于同级 `lispacerelease`，Python 已加入 PATH，`JAVA_HOME` 与 `ANDROID_HOME` 分别指向 JDK 和 SDK。目录、版本和文件名应按当前环境调整。

```powershell
$sourceRoot = (Get-Location).Path
$updateRepo = Join-Path (Split-Path -Parent $sourceRoot) 'lispacerelease'
$releasePython = 'python'
$releaseVersion = ((Get-Content 'android/version.properties' | Where-Object { $_ -like 'versionName=*' }) -split '=', 2)[1].Trim()
$releaseApk = Join-Path $sourceRoot "out/RedMagicDuo-v$releaseVersion-release.apk"
$releaseNotes = Join-Path $sourceRoot "docs/releases/v$releaseVersion.md"
Set-Location $updateRepo
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw '更新仓库同步失败' }
$releasePublishArgs = @(
    'tools/publish.py', '--app', 'redmagic-duo',
    '--apk', $releaseApk, '--notes-file', $releaseNotes,
    '--sdk', $env:ANDROID_HOME, '--java-home', $env:JAVA_HOME
)
& $releasePython @releasePublishArgs --dry-run
if ($LASTEXITCODE -ne 0) { throw '发布预检查失败' }
```

预检查只读取本地已同步清单与 APK，不修改 GitHub。发布身份需有更新仓库 Contents 写权限，并满足 `main` 分支规则；工具支持 Git Credential Manager、GitHub CLI 或 `GH_TOKEN` / `GITHUB_TOKEN`。私钥、密码和令牌不写入源码或清单。

核对更新说明和发布计划后，在同一窗口执行正式发布：

```powershell
& $releasePython @releasePublishArgs
if ($LASTEXITCODE -ne 0) { throw '发布未确认成功，请核对公网清单与附件' }
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw '发布后同步失败' }
& $releasePython tools/validate.py
if ($LASTEXITCODE -ne 0) { throw '本地清单验证失败' }
Set-Location $sourceRoot
```

随后执行下面的公网核验。工具说明与协议由[更新仓库](https://github.com/liligit1815/lispacerelease)维护。

## 更新清单示例

固定入口为 [updates/redmagic-duo.json](https://raw.githubusercontent.com/liligit1815/lispacerelease/main/updates/redmagic-duo.json)。完整、可直接交给客户端解析器检查的示例保存在 [examples/redmagic-duo.json](examples/redmagic-duo.json)，内容是 2026-10-30 发布的 `20690` 快照，对应以下安装包与更新说明：

```json
{
  "schemaVersion": 1,
  "appId": "redmagic-duo",
  "packageName": "ls.augment.com",
  "release": {
    "versionCode": 20690,
    "versionName": "2.0.0-alpha1-test20690",
    "minSdk": 35,
    "publishedAt": "2026-10-30T02:14:55Z",
    "notes": "- 修复小米运动健康点击“去绑定”后返回仍无法完成账号绑定的问题。\n- 修复通知堆叠滚动后首条通知顶部被裁切、内容显示不完整的问题。\n- 优化通知堆叠在锁屏、通知中心切换及关闭功能时的显示恢复。\n- 更新后请重启手机。\n- 取消工作台文件流转能力，取消QQ作用域，请务必在LSP框架中取消勾选QQ作用域，经反馈Hook QQ易出现账户风险提示，不Hook无法实现文件流转，故取消此功能",
    "apk": {
      "url": "https://github.com/liligit1815/lispacerelease/releases/download/redmagic-duo-v20690/redmagic-duo-20690.apk",
      "size": 14502827,
      "sha256": "fffe1e1c0c8d2fb351ab4a31edd6d96d9ec72b09f1c5bcf531023495f0b2cf5b",
      "certificateSha256": "4e5c23c41de3d7d56f120309e9fe8dab7d53483c50ef18a176e00558abf7b8cb"
    }
  }
}
```

此示例不能复制为下一版推送数据。包名、版本、`minSdk`、附件名、大小、两个摘要及发布时间由发布工具读取 APK 或生成；发布者只提供 APK 与更新说明。

| 字段 | 含义与约束 |
|---|---|
| `schemaVersion` | 数字 `1`，不能写成字符串 `"1"` |
| `appId` / `packageName` | 固定为 `redmagic-duo` / `ls.augment.com`，不能使用其他软件的清单 |
| `release` | 当前选定的发布对象；首次无发布时为 `null`，不能删除字段 |
| `versionCode` / `versionName` | 实际 APK 的内部版本号与显示版本名；前者为 1–2100000000 的整数，后者最长 100 个字符；只增加显示版本名不会触发更新 |
| `minSdk` | 实际 APK 的最低 Android API，当前为 `35`；超过手机 API 时提示不兼容 |
| `publishedAt` | UTC ISO 8601 时间，以 `Z` 结尾；由发布工具生成，不能直接填北京时间或 `+08:00` |
| `notes` | 更新弹窗展示的文字，最长 12000 个字符；换行使用 JSON 的 `\n` 转义；清单整体不超过 64 KiB |
| `apk.url` | 本更新仓库公开 Release 的 HTTPS `.apk` 附件直链，无查询参数或片段；不能使用 `releases/latest`、网页链接、raw APK 或镜像地址 |
| `apk.size` | APK 的实际字节数，正整数；发布工具限制不超过 512 MiB |
| `apk.sha256` | APK 文件 SHA-256，64 位十六进制字符串 |
| `apk.certificateSha256` | 发行签名证书 SHA-256，64 位十六进制字符串；与文件 SHA-256 不同，必须匹配现有发行证书 |

## 发布后联网核验

以下命令从匿名公网入口重新下载清单和 APK，在电脑上核对发布数据。手机运行更新功能无需电脑工具。示例为 Windows PowerShell；Python、JDK、SDK 和源码路径按本机实际环境调整。`$releasePython` 应指向可用的 Python 3，`JAVA_HOME` 应指向 JDK，`ANDROID_HOME` 应指向 SDK。`tools/test-app-updates.py` 需要 `org.json 20240303` 的缓存 JAR，缺少缓存时使用 `--json-jar <JAR路径>`。将 `$expectedVersionCode` 改为本次拟推送的内部版本号，防止把仍在缓存中的上一版清单误认作发布完成。

先用客户端实际的 `AppUpdateManifest` / `AppUpdatePolicy` 解析公网清单；任何命令报错都应停止后续操作：

```powershell
# 在源码仓库根目录执行
$releasePython = 'python'
$expectedVersionCode = 20690  # 替换为本次实际推送版本
$androidSdk = $env:ANDROID_HOME  # 或设为 android/local.properties 中的实际 sdk.dir
$sdkTools = Join-Path $androidSdk 'build-tools/35.0.0'
$checkDir = Join-Path (Get-Location) 'audit-output/published-update-check'
New-Item -ItemType Directory -Force -Path $checkDir | Out-Null
$manifestPath = Join-Path $checkDir 'redmagic-duo.json'
$manifestUrl = 'https://raw.githubusercontent.com/liligit1815/lispacerelease/main/updates/redmagic-duo.json'
Invoke-WebRequest -UseBasicParsing -Uri $manifestUrl -Headers @{'Cache-Control'='no-cache'} -OutFile $manifestPath -ErrorAction Stop
& $releasePython tools/test-app-updates.py --java-home $env:JAVA_HOME --manifest $manifestPath
if ($LASTEXITCODE -ne 0) { throw '客户端清单解析未通过' }
$feed = Get-Content -LiteralPath $manifestPath -Raw -Encoding UTF8 | ConvertFrom-Json
if ($null -eq $feed.release) { throw '公网清单尚未选择可下载版本' }
$published = $feed.release
if ($published.versionCode -ne $expectedVersionCode) { throw '公网清单未指向本次拟推送版本，请稍后重新下载核验' }
$published | Select-Object versionCode, versionName, minSdk, publishedAt
```

确认以上版本等于本次拟推送版本后，在同一窗口下载 APK，校验字节数、哈希、内部元数据和发行证书：

```powershell
$apkPath = Join-Path $checkDir "redmagic-duo-$($published.versionCode).apk"
Invoke-WebRequest -UseBasicParsing -Uri $published.apk.url -MaximumRedirection 5 -OutFile $apkPath -ErrorAction Stop
$actualHash = (Get-FileHash -LiteralPath $apkPath -Algorithm SHA256).Hash.ToLowerInvariant()
if ((Get-Item -LiteralPath $apkPath).Length -ne $published.apk.size -or $actualHash -ne $published.apk.sha256) {
    throw '公网 APK 大小或 SHA-256 与清单不符'
}
$badging = (& "$sdkTools/aapt2.exe" dump badging $apkPath) -join "`n"
if ($LASTEXITCODE -ne 0) { throw '无法读取 APK 元数据' }
$identity = [regex]::Match($badging, "package: name='([^']+)' versionCode='([0-9]+)' versionName='([^']+)'")
$minimum = [regex]::Match($badging, "(?m)^(?:minSdkVersion|sdkVersion):'([0-9]+)'")
if (-not $identity.Success -or -not $minimum.Success -or
    $identity.Groups[1].Value -ne $feed.packageName -or
    [int]$identity.Groups[2].Value -ne $published.versionCode -or
    $identity.Groups[3].Value -ne $published.versionName -or
    [int]$minimum.Groups[1].Value -ne $published.minSdk) {
    throw '公网 APK 的包名、版本或最低系统版本与清单不符'
}
$signature = (& "$sdkTools/apksigner.bat" verify --verbose --print-certs $apkPath) -join "`n"
if ($LASTEXITCODE -ne 0) { throw '公网 APK 签名验证失败' }
$certificates = [regex]::Matches($signature, '(?m)^Signer #\d+ certificate SHA-256 digest: ([0-9a-f]+)')
$releaseCertificate = '4e5c23c41de3d7d56f120309e9fe8dab7d53483c50ef18a176e00558abf7b8cb'
if ($certificates.Count -ne 1 -or
    $certificates[0].Groups[1].Value -ne $published.apk.certificateSha256 -or
    $certificates[0].Groups[1].Value -ne $releaseCertificate) {
    throw '公网 APK 与清单或既有发行证书不符'
}
Write-Output "公网 APK 校验通过：$($published.versionName) ($($published.versionCode))"
```

本地示例也可交给同一解析器核对：

```powershell
& $releasePython tools/test-app-updates.py --java-home $env:JAVA_HOME --manifest docs/examples/redmagic-duo.json
if ($LASTEXITCODE -ne 0) { throw '本地清单示例解析未通过' }
```

下载能否从手机成功完成，还取决于该手机的网络能否访问 `raw.githubusercontent.com`、`github.com` 及 GitHub 官方附件重定向域名。手机端通过本机网络检查、下载并校验安装包，再交由系统安装器完成更新。

## 手机更新流程

具有在线更新功能的旧版可通过“关于 → 检查更新”获取新版。`20518` 是首次接入在线更新的版本；更早的版本需先手动安装。新版内部版本号必须高于已安装版本，手机系统须满足安装包的 `minSdk`，覆盖安装须使用同一发行签名。

1. 打开红魔 Duo 后自动检查更新，也可在“关于 → 检查更新”手动检查。发现新版时显示当前版本、新版和更新内容，底部提供“跳过此版本”“稍后提醒”“立即更新”。
2. 点击“立即更新”下载并校验安装包，应用在前台时继续打开系统安装流程；按系统提示允许红魔 Duo 安装此来源的应用，再完成安装确认。如果下载期间离开应用，返回后点击“安装”继续。取消安装后可以重新手动检查和安装。
3. 安装完成后重新打开红魔 Duo，按功能页提示重启作用域。原有配置保留，再次检查会显示“已是最新版本”。

自 `20679` 起，每次应用从后台重新进入前台时检查一次，内部页面跳转和旋转不重复检查；无新版或网络失败时保持静默。“跳过此版本”仅屏蔽所选版本，后续新版正常提醒；“稍后提醒”对当前版本延后 24 小时，到期后再次打开时提醒，期间出现更新的版本仍可提示。手动检查忽略跳过和延后设置。大小、摘要、包名、版本或签名不匹配时，客户端阻止安装并显示原因。

Debug 签名或历史其他证书安装的应用可能无法覆盖更新。在线更新通过手机端检查、下载、校验和系统安装器完成，用户无需安装电脑脚本、服务或专用驱动。

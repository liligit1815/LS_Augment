## 2. 新电脑准备工具

| 工具 | 要求 |
|---|---|
| Git | 能访问 GitHub；Windows 同时安装 Git Bash |
| JDK | 17 或以上；本轮实际验证 JDK 21.0.10，设置 `JAVA_HOME` 并可运行 `java`／`javac` |
| Android SDK | Platform 36、Build Tools 35.0.0、NDK 27.2.12479018、CMake 3.22.1 或以上；可通过 Android Studio SDK Manager 安装 |
| Python | Python 3，需可通过 `python` 调用；本轮验证 3.12 |
| Node.js | 网页开发需要 >=22.13.0；本轮验证 24.14.1、npm 11.16.0 |
| 网络 | 首次构建需要访问 Gradle、Google Maven、Maven Central 与 npm 配置的包源 |

不需要全局安装 Gradle。仓库 Wrapper 固定 Gradle 8.13，Android Gradle Plugin 固定 8.13.2；使用已提交的依赖配置和 `package-lock.json`，不要为了启动而随意升级版本。

在系统环境变量中设置 `ANDROID_HOME` 为本机 SDK 目录，并在新开的终端中生效。Windows 常见路径是 `%LOCALAPPDATA%\Android\Sdk`；每台机器实际路径可能不同。也可在 `android/local.properties` 写入本机 `sdk.dir`，例如 `sdk.dir=C:/Users/你的用户名/AppData/Local/Android/Sdk`，该文件已忽略，不提交 Git。

## 3. 拉取和验证 Android

在准备存放项目的目录执行：

```bash
git clone https://github.com/liligit1815/LS_Augment.git
cd LS_Augment
git switch main
git status --short
git log -1 --oneline
```

正常首次拉取后 `git status --short` 没有输出。若另一台电脑已有未提交工作，先保留或提交自己的修改，再使用 `git pull --ff-only origin main`；不要用强制重置覆盖已有工作。

Windows PowerShell 构建：

```powershell
.\android\gradlew.bat -p android :app:assembleDebug
python tools/check-project.py
```

Windows 在 Git Bash 中，或 Linux／macOS 的 Bash 中，运行以下入口；非 Windows 平台未在本轮实测：

```bash
bash build-module.sh
python tools/check-project.py
bash tools/run-java-tests.sh
bash build-source.sh
```

`build-module.sh` 调用 Python、Bash 和 `sha256sum`。Linux／macOS 如果只有 `python3`，需先准备可用的 `python` 命令。Windows 不要把系统的 WSL 占位启动器当作 Git Bash；在 Git Bash 窗口运行即可。`.gitattributes` 保证 Shell 资源以 LF 检出，编辑时使用 UTF-8 无 BOM。

构建成功后，原始 APK 在 `android/app/build/outputs/apk/debug/app-debug.apk`；脚本整理的 APK、源码 ZIP 与校验值在 `out/`。这些均为可重新生成的文件，不提交 GitHub。

## 4. 启动和验证网页原型

在 `ui-preview/` 目录执行：

```bash
npm ci
node scripts/test-current-prototype.mjs
node scripts/test-prototype-settings.mjs
node scripts/test-feature-groups.mjs
npx tsc --noEmit
npm run build
npm run dev -- --host 127.0.0.1 --port 3000
```

访问 `http://localhost:3000/#home`。网页只操作样例及浏览器状态，不控制手机。Windows 若 PowerShell 阻止 npm 脚本，可调用 `npm.cmd`／`npx.cmd` 或改用 Git Bash。`npm ci` 根据已提交的锁文件安装依赖，无需复制旧机器的 `node_modules`。

## 5. 必须单独保留的资料

- **原 APK 的签名私钥与密码**：不在 GitHub。继续开发和生成调试 APK 不依赖它，但覆盖安装到使用原签名的手机需要同一私钥。公开 `tools/signing/dev41-test-cert.pem` 不能签名。构建可通过 `LS_AUGMENT_KEYSTORE`、`LS_AUGMENT_STORE_PASSWORD`、`LS_AUGMENT_KEY_ALIAS`、`LS_AUGMENT_KEY_PASSWORD` 注入签名，私钥放仓库外。
- **手机与浏览器配置**：如需接续具体测试状态，分别使用模块／原型的备份功能。源码拉取不会迁移这些状态。
- **历史证据和参考 APK**：精简后原厂 APK、旧截图输出、日历原始表格及本地 `design-qa.md` 不随 Git 分发。现存生成的 Java 日历数据、JSON、图片与字体足以常规构建；重跑取材、图像对照或真机专项脚本时再准备相应输入。
- **设备环境**：真实功能验证仍需要匹配的红魔手机、Root、支持 libxposed API 102 的框架及对应原厂组件。只编译源码不需要连接手机。

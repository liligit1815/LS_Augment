# 红魔Duo UI规范

更新日期：2026-10-02。自 test20426 起执行，适用于所有新增、调整和重构的 Android 原生页面、网页原型、弹窗及多级功能界面。实施前必须阅读本规范；后续界面均按本规范设计和验收。

## 设计基准与优先级

- 主页、模块、关于是现行视觉基准。各功能页沿用同一背景、配色、卡片、字号、图标、开关和交互，不为单个功能另设视觉体系。
- 复用 `UiKit`、`AppearanceController`、`LiquidGlassLayout`、`GlassIcon` 及既有输入、弹窗和折叠组件。借鉴 MIUIX 时只在现有体系内改善交互，不引入与主页不一致的大标题、大卡片或多层装饰。
- 用户最新明确要求优先于本规范；本规范优先于旧原型、旧截图和历史发布记录。test20421 的“首张功能卡片与主页聚合卡片顶边对齐”已被本规范的紧凑导航间距替代。历史记录只用于追溯。
- 功能必须由手机端实现；网页原型与开发工具不能成为用户使用模块的前提。

## 导航与纵向间距

二级及更深页面采用“顶部操作栏 → 路径导航 → 内容”的结构。路径导航显示当前位置并允许返回上级；已有路径标题时，不再重复放置页面大标题。

| 项目 | 规范 |
|---|---|
| 路径导航底边 → 首个分组标题顶边 | **总计 8–12dp，默认 8dp** |
| 无分组标题的页面 | 路径导航底边 → 首个内容控件顶边同样为 **8–12dp，默认 8dp** |
| 首个分组标题额外上边距 | **0dp**；导航框架已经提供 8dp 间距，不得重复添加 |
| 分组标题 → 所属卡片 | 16dp，与现有分组样式一致 |
| 常规页面左右内容边距 | 16dp |
| 普通相邻卡片间距 | 使用现有 8–12dp 节奏，不以空白填满屏幕 |
| 主页既有节奏 | 标题 → 搜索卡片 22dp；搜索卡片 → 应用列表 12dp |

“总间距”包括路径栏下方占位、内容容器上内边距及首个标题上外边距。以路径栏和标题控件的实际布局边界测量，不以字形墨迹边缘或截图物理像素直接替代 dp。状态栏安全区不计入这段距离。

**禁止**根据主页标题高度、搜索栏高度或主页卡片绝对位置计算二级页面顶部留白。不得用透明 View、空标题、固定高度容器补回旧的对齐空白。系统字体放大时允许文字控件自然增高，导航后的间距仍保持 8–12dp；横屏、宽屏也不因画面空旷而增加这段留白。

公共实现：`UiKit.DETAIL_CONTENT_GAP_DP = 8`，由 `detailChrome()` 统一提供；`detailPage()` 复用该框架。分组标题使用 `addDetailSectionTitle()`，首个标题不再添加上边距。嵌入式编辑器只提供内容，间距由宿主统一承担。

## 卡片、文字与控件

- 卡片优先使用 `preferenceCard()` / `card()`，服从用户的圆角或直角卡片设置，保留公共玻璃材质和浅色、深色主题，不为单页硬编码背景、描边和透明度。
- 标题、说明、状态使用 `UiKit.text()` 的公共字级和色彩角色，保留系统字体缩放。路径栏沿用 13.225sp；不得重复应用紧凑字号转换，也不得用缩小字体弥补布局溢出。
- 普通导航行复用 `preferenceRow()` / `groupRow()`；功能行复用 `featureRow()`。开关、帮助入口和末列展开箭头保持同列对齐，不因功能名称长短移动位置。
- 右向箭头仅表示进入下一级页面。当前页操作使用动作按钮，已展示的链接、更新包等内容可直接点击复制，并明确提示复制结果，无需另设“查看链接”按钮。属于某个功能的内容和操作放入该功能的展开区域，不另建带右箭头的独立导航行。功能行的向下／向上箭头只表示展开／收起。
- 延续现有尺寸：常规导航行至少 48dp，功能行至少 44dp；开关轨道 46×28dp，滑块 22×22dp，展开列 25×44dp。输入框和星期选择等主要编辑控件至少 48dp 高，不为压缩留白缩小触控区域。
- 使用既有图标资源与统一线条样式。辅助说明放在对应功能帮助或明确的状态位置，不堆叠重复的说明卡片。
- 更新包条目优先展示起止版本、地区和明确标注的固件分支，省略已识别格式中的随机前缀、重复编码和下载接口路径；复制仍使用完整原始链接。不得将固件分支当作设备型号，或未经确认换算为系统宣传版本；时间注明“提取”，避免误解为发布日期。

## 交互与功能状态

- 开关控制真实功能是否生效；展开只控制参数显示。默认开启后展开，关闭后收起，关闭状态不能展开；单独收起不关闭已启用功能。
- 关闭功能保留有效参数和已有用户数据。应用显示恢复、素材管理等确有必要在关闭状态使用的工具，可沿用明确标注的既有例外，不能把配置编辑误表现为功能已经启用。
- 有账号、权限或服务前提的功能，开启前检查条件，不满足时提供明确原因及可执行入口，不能只改变开关外观。
- 小米运动健康必须核验绑定账号后才允许开启功能，已绑定状态显示实际小米账号；倍率、随机计划和上限分别受自己的开关控制。
- 自动保存保留原有行为，失败或无效输入必须反馈。普通功能页不重复添加“设置自动保存”“生效说明”等固定页脚，也不堆放与当前操作无关的“运行与帮助”分组。
- 返回、路径跳转、重建和滚动恢复保持一致；有未提交草稿的编辑器继续提供既有退出保护。加载或状态变化不能让内容跳动或挡住操作。

## 设计与验收流程

1. 开始改动前，阅读本规范和涉及的公共组件，查找主页、模块、关于及相似功能页作为参照。
2. 优先修正或复用公共组件；页面使用公共导航、卡片和输入组件，不再复制一套仅适用于当前功能的布局。
3. 使用同一设备、主题、显示比例、字号、滚动位置和功能状态比较截图；间距用实际布局边界按设备密度换算。网页原型采用对应的逻辑尺寸，不能直接照搬手机物理像素。
4. 检查路径到首个标题或控件的总间距为 8–12dp，确认没有多层叠加的顶部空白；同时检查分组标题、卡片和开关列的对齐。
5. 按变更范围检查展开、关闭、返回、键盘、必要前提及草稿保护。公共框架改动须覆盖有分组标题和直接显示卡片的页面，保留已有功能配置。
6. 在目标设备检查最终画面；涉及适配的改动还需检查大字号、横屏或宽屏。只完成编译或普通字号检查时，不宣称其他状态已验收。
7. 交付说明记录版本、实际检查结果与限制。调整设计规则时同步本规范、公共实现和对应回归检查，不让旧的测量标准与现行规则冲突。

## 本次规则的来源

用户于 2026-10-02 明确要求将导航到分组标题的距离控制在 8–12dp，并将规则写入红魔Duo UI规范，后续界面均遵循。此前 test20425 真机测得小米运动健康导航到“账号绑定”约 35dp，其中额外对齐占位约 27dp；test20426 改用公共 8dp 间距，并去掉首个分组叠加的上边距。
